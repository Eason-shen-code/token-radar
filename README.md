# AI 算力价格监测台

从 `Token采购比价报告_2026-10-15.html` 逆向重建的自动化监测系统。原报告是一次性人工抓取 + 手工整理的静态 HTML；本项目把它的**数据来源、计算口径、校验逻辑**全部结构化，交给脚本每日自动跑。

## 一、原报告是怎么来的（逆向结论）

报告的"数据来源与抓取时间"一节自己泄露了答案：22 条来源全部标注 `WebFetch` / `WebSearch` + 日期 `2026-10-15`。

| 环节 | 原做法 | 现在的自动化 |
|---|---|---|
| 取数 | AI 逐页 WebFetch 官方文档 + WebSearch 营销页 | Node 脚本定时抓取，能确定性解析的源全自动更新 |
| 折算 | 解析时人工换算，脚本只做汇总 | `月单价 ÷ (额度/100万)` 运行时重算，公式写死在代码里 |
| 校验 | 靠人眼核对 | 与基线逐字段比对，偏差自动生成涨跌事件 |
| 输出 | 一次性写死的 HTML | 数据与页面分离，数据变页面自动变 |

**报告的核心计算口径**（已复现到代码）：

- 折算单价（订阅套餐）= 月单价 ÷ (单账号月额度 Token 数 ÷ 1,000,000)，以"额度用满"为下限假设
- 官方综合单价（按量）= (2×输入 + 1×输出) ÷ 3，按输入:输出 = 2:1 混合、不含缓存命中
- 实测单价 = 实际费用 ÷ 实际消耗 Token（含缓存命中、时段折扣）
- 排序：套餐按促销折算价、按量按官方综合价，`—/待实测/待核实` 固定沉底

**报告里 6 张表 = 6 个模型族**：GLM-5.3、DeepSeek V4 Pro、DeepSeek V4.1 Flash、豆包 Seed、千问 Qwen3.8、Kimi K3/K2.7-Code，外加移动云专项说明。

## 二、为什么不能"全自动抓 22 个源"

实测结论（2026-11-03 逐源验证）：

- **能确定性抓的**（服务端渲染、有价格文本）：智谱文档 `.md`、DeepSeek 文档 HTML 表格、OpenRouter 公开 JSON API —— 归为 **A 级**，每次运行数值自动更新
- **抓不到数值的**：阿里百炼、百度千帆、天翼云、联通云（WAF 412）、Kimi（纯前端渲染）、火山活动页（价格在 JS 里）—— 归为 **B 级**，只能做**内容指纹比对**：抓正文里所有"数字＋元"表述，哈希后与昨日比，变了就报警，数值仍需人工确认
- **没有公开价格的**：移动云政企报价 —— 归为 **C 级**，人工基线 + 定期复核

任何声称"20 家云厂商价格全自动抓取实时同步"的方案，都是忽略了这个现实。本系统的处理方式是**分级标注新鲜度**，而不是假装全都实时。

## 三、目录结构

```
token-radar/
├─ config/sources.json     抓取源注册表（A/B/C 分级、URL、解析类型、汇率）
├─ data/
│  ├─ baseline.json        从原报告逆向出的结构化基线（6 模型族 / 39 行）
│  ├─ latest.json          最新一次抓取结果（页面数据源）
│  ├─ snapshots/YYYY-MM-DD.json  每日快照
│  ├─ changelog.json       价格变动事件日志（保留 180 天）
│  └─ watch-state.json     B 级源的页面指纹状态
├─ scripts/
│  ├─ http.mjs             抓取工具（超时/重试/UA/HTML 转文本）
│  ├─ parse.mjs            各源解析器（markdown 表格 / HTML 表格 / JSON）
│  ├─ run.mjs              主流程：抓取→解析→计算→比对→落盘
│  ├─ build.mjs            把数据内联进单文件页面
│  └─ serve.mjs            本地预览服务器
├─ public/
│  ├─ template.html        页面模板（移动优先，明暗双主题）
│  ├─ index.html           生成物：44 KB 单文件，可直接分享
│  └─ data.json            同源数据，供二次开发
└─ 更新价格.cmd            双击即跑
```

## 四、怎么用

```bash
cd token-radar
node scripts/run.mjs      # 抓取 + 计算 + 比对
node scripts/build.mjs    # 生成 public/index.html
node scripts/serve.mjs    # 本地预览 http://127.0.0.1:4173
```

Windows 下双击 `更新价格.cmd` 等同执行前两步。

## 五、定时更新

已配置每日 **08:30** 自动执行抓取 + 重建页面。自动化任务的执行依赖本机处于开机状态；若当天未开机，下次运行会补上最新价格（不追溯补抓历史）。

## 六、首次运行就抓到的价格变动

原报告（2026-10-15）标注 DeepSeek 官方 API 为"缓存命中/未命中扁平计价，已取消峰谷时段定价"。

2026-11-03 实测抓取：**DeepSeek 已恢复峰谷分时计价**，且价格大幅上调。

| 项目 | 报告值 | 实测空闲时段 | 实测高峰时段 | 变化 |
|---|---|---|---|---|
| V4 Pro 输入（缓存未命中） | 3.00 | 4.50 | 9.00 | +50% / +200% |
| V4 Pro 输出 | 6.00 | 13.50 | 27.00 | +125% / +350% |
| V4 Pro 官方综合单价 | 4.00 | 7.50 | 15.00 | +87.5% / +275% |
| V4.1 Flash 输出 | 2.00 | 4.00 | 8.00 | +100% / +300% |
| V4.1 Flash 官方综合单价 | 1.33 | 2.00 | 4.00 | +50.4% / +200% |

这直接推翻了原报告第二节的结论：按常态化高峰时段计费，DeepSeek 官方 API 已不再是"综合价 4.00 元/百万"的性价比基准线，而是 7.50~15.00 元/百万。同口径下，火山 Coding Plan Pro 的折算价 0.24~0.98 元/百万的差距从"约 4 倍"拉大到"约 8~60 倍"。

另有一处结构性变化：原报告引用的华为云 `support.huaweicloud.com/Token-plan-maas` 文档路径已 404，说明其文档站做过改版，相关档位数据需重新核验。

## 七、云服务接入

应用已开通 WorkBuddy 云服务（应用 ID `wbapp_WrIQWYOUJjbr1mwyDHziWZ`），把「价格历史」从页面内置数据升级为云端持久化。

### 数据表

| 表 | 用途 | 权限 |
|---|---|---|
| `price_snapshots` | 每次抓取的元信息，一天一行（抓取时间、A/B 级源数量、报价条数、变动条数） | 公开读，客户端禁写 |
| `price_quotes` | 各平台官方按量报价明细，按日期归档 | 公开读，客户端禁写 |
| `price_diffs` | 价格变动事件日志 | 公开读，客户端禁写 |

三张表都开了 RLS，只建了 SELECT 策略，没有 INSERT/UPDATE/DELETE 策略—— 匿名端只能读，写入必须走管理端（`exec_sql`）。这条边界已实测：带 publishableKey 的写请求返回 `DATABASE_42501 permission denied`。

### 写入路径

`scripts/sql-sync.mjs` 把 `data/latest.json` 转成 `.cache/sync-1..5.sql`（快照 upsert、变动/报价先删后插），由每日自动化任务通过管理端逐条执行。页面端只读，不持有任何写权限。

### 页面读取路径

页面加载先用内置快照即时渲染（保证无网也能看），随后异步从云端拉最新快照 + 报价 + 变动 + 历史序列，成功后原地重渲染并把顶部标签切成「云端已同步」。读取失败时顶部变「云端离线」并显示具体原因，页面回退到内置快照，不会白屏。

因为数据来自云端，**每日抓取不再需要重新发布页面** —— 这是接入云服务后省掉的最大一步。

### SDK 加载方式

`@tencent-ai/workbuddy-cloud-sdk` 的 IIFE 产物已 vendor 到 `public/vendor/workbuddy-cloud-sdk.js`，并由 `build.mjs` 内联进 `index.html`。原因有两条：jsdelivr CDN 在本机网络不可达；分享站点对静态资源有 `sharecode` 门禁，外链请求会 403。内联后单文件 123 KB，零外部依赖。

## 八、维护约定

- **要新增源**：在 `config/sources.json` 加一条，写入 `id/name/url/type/tier`；能解析的再加适配器到 `scripts/parse.mjs`
- **要改基线价格**：改 `data/baseline.json`，同时更新 `version` 字段（页面顶部会显示）
- **汇率**：`config/sources.json` 里 `fx.usdCny` 为人工维护值，用于 OpenRouter 参考价折算
- **B 级源报了变更**：到对应 URL 核对，确认后改 `baseline.json`，否则下一轮会持续报警

## 九、定时执行：能放到云端吗

**结论：云服务本身没有定时触发器。** 它只提供数据库、登录、存储、大模型调用四类能力，没有 cron / 定时函数 / 触发器。所以「每天 8 点自动跑」不可能只靠云服务自己完成，必须有外部定时器。

已经做好的准备：抓取链路已与运行环境解耦。任何能跑 Node 的地方，两条命令就能完成一次更新：

```bash
node scripts/run.mjs     # 抓取 + 计算
node scripts/push.mjs    # 推送云端（唯一需要的凭据是 INGEST_TOKEN）
```

写入走 `ingest_snapshot` 这个 SECURITY DEFINER 函数，令牌校验通过才能写；令牌存在 `app_config` 表里（RLS 开启、无任何策略、anon 读不到）。页面端仍然只读。

### 三种触发方式

| 方式 | 需要什么 | 稳定性 | 说明 |
|---|---|---|---|
| **GitHub Actions**（推荐） | 一个 GitHub 私有仓库 + 一个 Secret | 高 | 工作流已写好：`.github/workflows/crawl.yml`，UTC 00:00 = 北京 08:00。免费额度足够，历史运行可查 |
| **腾讯云函数 SCF** | 腾讯云账号 | 高 | 把 scripts + config + data 打成 zip，配定时触发器 `0 0 8 * * *`，环境变量放 INGEST_TOKEN |
| **常驻 Node 服务** | 无 | 未验证 | 把站点从静态改成 node runtime，进程内 `setInterval` 自己抓自己写。理论上零外部依赖，但沙箱进程是否 7×24 常驻未验证，重启会丢定时器 |

### GitHub Actions 启用步骤

代码仓库：https://github.com/Eason-shen-code/token-radar （main 分支，2026-11-04 首推）

1. ~~推送代码~~ —— 已完成。`config/ingest.json` 已被 .gitignore 排除，写入令牌不在仓库里
2. 仓库 Settings → Secrets and variables → Actions → 新建 `INGEST_TOKEN`，值取本机 `config/ingest.json` 的 `ingestToken`（**这一步没做，定时任务会在推送环节失败**）
3. Actions 页面点一次 `Run workflow` 手动验证，跑通后再交给 cron

### 已知限制

- GitHub 的 schedule 不是精确定时，高负载时段可能延迟 5–20 分钟，别指望 08:00:00 准时
- 抓取源里 B 级源（火山/阿里/百度等）仍是「内容变更监控」而非数值抓取，这一点不会因为搬上云端而改善
- 本地自动化任务（每日 08:30）目前仍然保留，和云端定时重复跑不会出问题（同一天的数据是 upsert，幂等）
